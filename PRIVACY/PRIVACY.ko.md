# Lucent 개인정보 처리방침

Lucent는 Android와 Windows용 노트 및 할 일 앱입니다. 이 방침은 이 앱이 기기 안에 무엇을 저장하고, 무엇을 기기 밖으로 보내며, 그 둘을 어떻게 통제할 수 있는지를 설명합니다. 여기 적힌 내용은 이 저장소에서 빌드되는 Lucent 자체에 관한 것입니다.

**최종 업데이트: 2026년 9월 25일**

## 1. 요약

- Lucent에는 계정도, 가입도, 개발자가 운영하는 서버도 없습니다. 개발자가 당신의 노트, 할 일, 파일, 사용 기록을 받을 수 있는 경로는 존재하지 않습니다.
- 노트, 할 일, 노트북, 체크리스트, 버전 기록, 어시스턴트 대화, 첨부파일, API 키, 각종 설정은 기기에 저장되며 저장 상태로 암호화됩니다.
- 앱에는 분석 도구도, 광고도, 텔레메트리도 없습니다.
- 네트워크를 쓰는 기능은 모두 선택 사항이며 기본적으로 꺼져 있습니다. 클라우드 어시스턴트, 웹 검색, 시맨틱 검색, 클라우드 백업, 자동 업데이트 확인이 여기에 해당합니다.
- 클라우드 어시스턴트를 쓸 때 메시지는 당신이 입력한 API 키의 제공자에게 기기에서 곧바로 전송됩니다. Lucent를 거치지 않습니다.
- 선택 사항인 온디바이스 모델은 전적으로 기기에서 답하며 어디에도 아무것도 보내지 않습니다.

아래에서 각 항목을 그 한계까지 포함해 자세히 설명합니다.

## 3. Lucent가 기기에 저장하는 것

Lucent에서 만든 모든 것은 기기 안의 앱 전용 비공개 저장 영역에 들어갑니다. 이 영역은 다른 일반 앱이 읽을 수 없고, 앱을 삭제하거나 앱 데이터를 지우면 함께 제거됩니다.

저장되는 내용은 다음과 같습니다.

- 노트: 본문, 서식, 태그, 색상, 고정 및 보관 상태, 체크리스트, 낙서, 링크, 버전 기록
- 할 일: 하위 할 일, 우선순위, 마감일, 반복 규칙, 알림, 메모, 버전 기록
- 노트북과 그 안에 정리한 항목
- 어시스턴트 대화와 메시지, 모델이 돌려준 사고 과정 포함
- 노트나 할 일에 추가한 첨부파일, 그리고 어시스턴트에게 보낸 첨부파일
- 가져온 글꼴과 로컬 모델 파일
- 설정: 선택한 제공자, 기본 URL, 모델 이름, API 키, 백업 비밀번호, 앱 잠금 자격 증명, 클라우드 백업 자격 증명
- 진단 로그: 진단 로그를 켜 둔 경우에 한합니다.

### 3.1 저장 상태 암호화

데이터베이스는 SQLCipher로 암호화됩니다. Android에서는 Room과 SQLCipher를 함께 쓰고, Windows에서는 함께 포함된 JDBC 드라이버를 SQLCipher 방식과 같은 종류의 256비트 키로 설정해 SQLite를 사용합니다. 노트, 할 일, 대화, 기록, 설정이 모두 이 데이터베이스 안에 있습니다.

첨부파일은 따로 암호화됩니다. 각 파일은 디스크에 쓰이기 전에 인증이 붙는 AES-256-GCM 컨테이너에 64 KiB 단위로 담깁니다. 디스크에 남는 파일 이름은 무작위 식별자이며, 앱에서 보이는 이름이 아닙니다.

백업도 언제나 암호화됩니다. 6절을 보십시오.

### 3.2 키와 비밀 정보

데이터베이스 키와 첨부파일 키는 기기에서 무작위로 생성한 256비트 값입니다. 당신이 입력한 무엇에서도 파생되지 않고, 평문으로 디스크에 기록되지도 않습니다. Android에서는 Android Keystore가 보관하는 키로 감싸 보호하며, 기기가 지원하면 하드웨어로 보호됩니다. Keystore를 쓸 수 없을 때는 기기 내 대체 경로로 물러섭니다. Keystore 문제로 데이터가 사라지지 않도록 각 키의 복구용 사본도 보관합니다.

API 키, WebDAV 비밀번호, 백업 비밀번호, 앱 잠금 자격 증명도 같은 암호화 경로로 저장되며 평문이 아닙니다. 앱 잠금 비밀번호와 보안 질문의 답은 아예 저장하지 않습니다. 남는 것은 솔트가 섞인 해시뿐이고, 그 해시에서 비밀번호 자체를 되살릴 수는 없습니다.

### 3.3 암호화가 하는 일과 하지 못하는 일

여기서 암호화가 지키는 것은 저장된 데이터입니다. 기기 밖으로 나간 데이터베이스, 첨부파일, 백업은 키 없이는 읽을 수 없습니다. 반대로 기기 잠금을 푼 상태에서 당신의 운영체제 계정으로 조작하는 사람에게는 지켜주지 못하며, 앱을 열어 둔 동안의 데이터도 지켜주지 못합니다. 표시하거나 편집하는 동안에는 복호화된 내용이 기기 메모리에 존재할 수밖에 없기 때문입니다.

Lucent는 이 점을 얼버무리지 않습니다. 암호화 라이브러리를 불러오지 못하거나 데이터베이스를 암호화 또는 복호화할 수 없으면, 성공한 척하지 않고 사실을 기록해 알립니다. 설정에는 저장된 값이 실제로 봉인되어 있고 올바르게 열리는지 확인하는 암호화 검사가 있습니다. 저장된 키로 데이터베이스를 복호화할 수 없으면 Lucent는 그것을 지우는 대신 한쪽으로 치워 두고 그 사실을 알립니다. 백업에서 복원할 수 있게 하기 위해서입니다.

Android의 홈 화면 위젯은 런처에 노트 제목이나 할 일 제목을 표시합니다. 위젯이 보여주는 내용은 그 화면을 볼 수 있는 사람이면 누구나 볼 수 있습니다. 위젯은 선택 사항이며 언제든 제거할 수 있습니다.

## 4. 절대 기기 밖으로 나가지 않는 것

기본 상태에서는 아무것도 나가지 않습니다. 노트, 할 일, 알림, 기록, 첨부파일, 로컬 검색, 온디바이스 어시스턴트는 네트워크 연결을 필요로 하지 않습니다.

구체적으로 Lucent에는 분석 SDK, 광고 SDK, 충돌 보고 서비스, 추적 식별자가 들어 있지 않습니다. 계정 체계도 없고, 어디론가 전송되는 기기 지문도 없습니다. 크래시 실드를 켜면 잡아낸 오류를 기기의 로컬 로그 파일에 기록할 뿐 전송하지 않습니다. 진단 로그도 같습니다. 기본적으로 꺼져 있고 로컬에만 기록하며, 당신이 직접 내보내 공유하기로 할 때에만 밖으로 나갑니다.

Lucent에는 서버가 없으므로 개발자가 당신의 데이터를 읽을 방법도, 대신 복구해 줄 방법도 없습니다.

## 5. 데이터가 기기 밖으로 나가는 경우

다음은 모두 선택 사항이고 기본적으로 꺼져 있으며 당신이 통제합니다. 어느 하나를 켜면 데이터는 앱에서 당신이 설정한 제3자에게 곧바로 전송됩니다. Lucent의 서비스는 없으므로 그런 곳을 거치지 않습니다.

### 5.1 클라우드 어시스턴트(API 키 직접 사용)

클라우드 모드의 어시스턴트는 당신이 마련한 API 키와 당신이 고른 제공자를 씁니다. Lucent는 OpenAI 호환, Anthropic 호환, Google 호환 요청 형식을 지원하며, OpenAI 호환 주소라면 DeepSeek이나 직접 운영하는 게이트웨이까지 포함해 무엇이든 됩니다. 여러 제공자 설정을 저장해 두고 바꿔 쓸 수 있습니다.

메시지를 보내면 Lucent는 설정된 기본 URL로 기기에서 HTTPS 요청을 보냅니다. 그 요청에는 다음이 들어갑니다.

- 당신의 메시지 본문
- 현재 기억 설정에 포함되는 지난 대화
- 어시스턴트의 동작을 정하는 시스템 지시
- 메시지에 첨부한 파일
- 답변에 필요한 노트, 할 일, 노트북, 검색 맥락과 어시스턴트가 호출한 도구의 결과

API 키는 그 요청의 인증 헤더로 해당 제공자에게만 전송되며 다른 어디에도 보내지 않습니다. 제공자가 받은 텍스트를 어떻게 다루는지는 그 제공자의 개인정보 처리방침을 확인하십시오. 그것은 당신과 제공자 사이의 약속이며, Lucent는 들여다볼 수도 통제할 수도 없습니다.

어시스턴트가 당신의 데이터를 몰래 바꾸지는 않습니다. 무언가를 쓰기 전에 무엇을 하려는지 먼저 보여주며, 이 확인 단계는 기본적으로 켜져 있습니다. 도구는 선택 사항입니다. 로컬 모델에는 전용 도구 스위치가 있고, 클라우드 어시스턴트의 도구 사용도 설정에서 끌 수 있습니다. 둘 중 하나를 끄면 모델은 대화는 할 수 있어도 노트와 할 일을 읽거나 고치지는 못합니다.

### 5.2 웹 검색

웹 검색은 기본적으로 꺼져 있습니다. 이것을 켜고 어시스턴트가 검색이 필요하다고 판단하면, Lucent는 검색어를 공개 검색 엔진으로 보냅니다. 엔진은 당신이 고르거나 '자동'으로 두면 됩니다. 자동은 결과가 나올 때까지 차례로 시도합니다. Bing, DuckDuckGo, Google, Brave, Mojeek, Yandex, Baidu, Sogou, 360 검색, 그리고 Wikipedia 검색 API입니다. 검색 API 키를 쓰지 않고 계정도 만들지 않습니다. 검색어는 기기 밖으로 나가고, 결과는 어시스턴트에게 전달되어 답변에 포함됩니다. 결과를 준 엔진은 검색어와 당신의 IP 주소를 봅니다. 웹 검색에는 에이전트 모드가 필요하고, 로컬 모델에서는 도구 스위치도 필요합니다. 블랙아웃 모드는 이를 완전히 막습니다.

### 5.3 시맨틱 검색

Lucent의 시맨틱 검색은 사용 중인 어시스턴트를 그대로 따르므로 따로 고를 것이 없습니다. 로컬 모델을 쓰는 동안에는 색인이 기기 안에 머물지만 현재 빌드에서는 구현되어 있지 않아 아무것도 나가지 않습니다. 클라우드 모델을 쓰는 동안에는 각 벡터를 만들기 위해 색인할 텍스트가 설정한 AI 제공자의 embeddings 엔드포인트로 전송되어 노트 텍스트가 기기 밖으로 나갑니다. 모델을 바꾸면 이 동작도 함께 바뀝니다.

### 5.4 클라우드 백업

클라우드 백업은 기본적으로 꺼져 있습니다. 켜면 이미 계정을 가진 WebDAV 호환 서비스(예: Nutstore, Nextcloud, Koofr 또는 그 밖의 WebDAV 서버)의 주소, 사용자 이름, 비밀번호를 입력합니다. Lucent는 `.lcb` 백업 파일을 지정한 서버의 폴더에 업로드하고, 복원을 위해 목록을 확인하고 내려받을 수도 있습니다. 파일은 업로드 전에 이미 암호화되어 있습니다. 서비스가 보관하는 것은 암호화된 파일이고, 입력한 자격 증명은 인증을 위해 그 서비스로 전송됩니다. 자동 업로드는 별도의 스위치이며 역시 기본적으로 꺼져 있습니다.

### 5.5 업데이트 확인

자동 업데이트 확인은 기본적으로 꺼져 있습니다. 이것을 켜거나 당신이 확인을 요청했을 때, 앱은 이 저장소의 공개 GitHub releases API에 최신 릴리스 정보를 요청해 버전 번호를 비교합니다. 이 요청에는 HTTPS 요청이 일반적으로 싣는 것(IP 주소, Lucent를 밝히는 User-Agent 등) 말고는 개인 정보가 들어가지 않습니다. 더 새로운 릴리스가 있으면 Lucent가 알려주고, 당신이 업데이트를 고를 때에만 GitHub에서 APK나 설치 프로그램을 내려받습니다.

### 5.6 공유와 내보내기

Lucent가 스스로 밖으로 보내는 일은 없습니다. 데이터를 다른 앱에 넘기는 기능은 둘뿐이고 둘 다 당신이 통제합니다.

- **내보내기.** 노트나 할 일을 Markdown, Word, PDF, Excel로 내보내거나 백업을 내보내면, 저장 위치를 당신이 고른 파일이 만들어집니다. 내보낸 문서는 일부러 암호화하지 않습니다. 내보내기의 목적이 다른 곳에서 읽히는 것이기 때문입니다. 그 파일을 얻은 사람은 누구나 내용을 읽을 수 있으니 적절하다고 판단하는 곳에 보관하십시오.
- **공유 시트 연동.** Lucent를 공유 대상으로 만드는 기능은 기본적으로 꺼져 있습니다. 켜면 Lucent가 다른 앱의 공유 시트에 나타나 텍스트와 파일을 받아들일 수 있게 되고, 시스템 공유 시트에도 공유 대상으로 나타납니다. 안으로 공유된 내용은 다른 모든 것과 같은 암호화된 데이터베이스에 저장됩니다. Lucent가 스스로 무언가를 보내지 않는다는 점은 달라지지 않습니다.

### 5.7 온디바이스 모델

GGUF 모델을 가져오면 어시스턴트는 llama.cpp로 그것을 기기에서 직접 실행할 수 있습니다. 이 모드에서는 어디에도 아무것도 보내지 않습니다. 답변 생성에 계정도, API 키도, 네트워크 요청도 관여하지 않습니다. 모델 파일은 기기에 남고, 앱을 떠나면 모델은 언로드됩니다. 로컬 도구는 별도 스위치이며 기본적으로 꺼져 있습니다. GPU 가속은 선택 사항이고 끌 수 있습니다.

### 5.8 도구함

노트와 할 일을 넘어, assistant에게 실제 도구함을 쥐여 줄 수 있습니다. 읽고 쓸 수 있는 작업 공간
폴더, 셸 명령, 문서 처리, 플러그인, 외부 서비스 연결입니다. 각각은 설정 → 도구함에서 따로
켜고 끌 수 있으며, 기기 밖으로 나가는 기능은 사용자가 켜고 기본적으로 먼저 확인한 뒤에만 움직입니다.

- **작업 공간.** 폴더는 사용자가 하나 고릅니다. assistant가 읽고 쓰는 모든 것은 그 안에 있습니다.
  '작업 공간 밖' 권한을 허용하지 않는 한 바깥 파일은 읽지 못하며, 바깥에 쓰는 일은 결코 없습니다.
- **명령.** 셸 명령 실행은 기본적으로 확인을 요청합니다. 실행은 이 기기에서, 작업 디렉터리는 작업
  공간 안에서, 제한 시간은 설정한 값대로이며, 모든 실행이 작업 기록에 남습니다.
- **문서.** Word, Excel, PowerPoint 파일은 Lucent 자체 코드가 기기에서 만들고 읽습니다. 변환이나
  생성을 위해 어디로도 전송하지 않습니다.
- **플러그인.** 선택 도구(Linux 환경, 문서 라이브러리가 있는 Python, LibreOffice, Node.js, 미디어
  및 OCR 도구)는 사용자가 요청할 때만 공식 배포처나 공개 미러에서 사용자의 저장 공간으로 바로
  내려받습니다. Lucent는 이에 대한 텔레메트리를 보내지 않습니다.
- **연결.** GitHub, Notion, Slack, Google Drive, OneDrive, GitLab, Jira, Linear, WebDAV, 그리고
  추가한 MCP 서버는 사용자가 제공한 토큰으로 기기에서 직접 접속합니다. 보내는 것은 요청한 그
  요청뿐이며, 목적지는 사용자가 설정한 서비스입니다. 중간에 Lucent 서버는 없고, 토큰은 기기에서
  암호화되어 저장됩니다.
- **기기 제어(Android).** 이 기능을 켜고 접근성 서비스를 활성화하면 화면 읽기, 탭, 입력, 스크린샷,
  앱 목록과 실행, 알림 읽기, 클립보드와 센서 사용이 가능합니다. 화면 읽기는 기기에서 이루어지며,
  이를 담은 도구 결과를 선택한 모델 제공자에게 보낼 때만 기기를 떠납니다. 이는 다른 메시지와 같은
  경로입니다.
- **기기에 남는 것.** 작업 공간, 변경 전 스냅숏, 작업 기록, 기억한 사실, 스킬 파일은 기기에
  남습니다. 작업 기록에는 도구 이름, 인수(300자로 줄임), 결과가 들어가며 암호화되어 저장되고 같은
  설정 화면에서 언제든 지울 수 있습니다.

## 6. 백업

백업은 당신이 만드는 단일 `.lcb` 파일입니다. 노트, 할 일, 버전 기록, 노트북, 대화, 첨부파일, 설정, API 키를 담을 수 있고, 선택에 따라 가져온 글꼴과 로컬 모델 파일도 담을 수 있습니다. 무엇을 담을지, 어디에 쓸지는 당신이 정합니다.

`.lcb` 파일은 모두 암호화됩니다. 방식은 두 가지입니다.

- **비밀번호 없음.** 앱에 내장된 키로 암호화됩니다. Lucent와 이 파일만 있으면 어느 기기에서든 복원되니 편리하지만, 파일과 앱 사본을 함께 손에 넣은 사람은 누구나 읽을 수 있다는 뜻이기도 합니다.
- **비밀번호 있음.** 키는 당신의 비밀번호에서 PBKDF2-HMAC-SHA256을 210,000회 반복해 유도되며 그 밖의 어디에도 존재하지 않습니다. 더 강력하지만 대가는 늘 그렇듯이 따릅니다. 복원에는 같은 비밀번호가 필요하고, 그것은 어디에도 저장되지 않으며, 잊어버린 비밀번호는 개발자를 포함해 누구도 되찾아 주지 못합니다.

비밀번호로 보호한 백업에는 나중에 비밀번호를 되찾을 수 있도록 보안 질문과 답을 선택적으로 붙일 수 있습니다. 이 옵션은 기본적으로 꺼져 있고, 백업의 강도는 비밀번호와 답 중 약한 쪽에 맞춰집니다. 답을 자신 외에는 아무도 모르는 질문을 고르십시오.

자동 백업을 켜면 당신이 고른 폴더에 쓰고, 설정한 수만큼 사본을 남기며, 설정해 둔 WebDAV 폴더로도 업로드할 수 있습니다. 어느 경우든 백업 파일은 같은 암호화 컨테이너입니다. 백업을 어디에 두고 몇 부를 남길지는 전적으로 당신의 결정이며, 삭제도 마찬가지입니다.

## 7. 기기 연동

Lucent의 특권 셸 연동은 선택 사항이고 기본적으로 꺼져 있으며, Lucent 바깥의 소프트웨어와 허가를 필요로 합니다.

Android에서는 Shizuku를 설치하고 그 서비스를 시작한 뒤 시스템에서 Lucent에 권한을 부여하면, 앱이 Shizuku를 통해 특권 작업을 실행할 수 있습니다. 이것은 일반 앱이 스스로 할 수 없는 일 중 당신이 분명하게 요청한 것을 수행하기 위해 존재합니다. 예를 들어 당신이 내려받은 앱 업데이트의 설치입니다. Lucent는 Shizuku를 스스로 시작할 수 없고, 스스로 권한을 부여할 수도 없으며, 연동을 켜고 권한을 부여하지 않는 한 이 경로로 아무것도 하지 않습니다. 권한은 Shizuku나 Android 설정에서 언제든 취소할 수 있고 Lucent에서 연동을 끌 수도 있습니다. 실제로 얻은 권한의 uid는 앱에 표시되므로 어떤 신분을 얻었는지 확인할 수 있습니다.

Lucent는 필요한 일반 Android 권한도 선언합니다. 각각 목적이 있으며 8절에 정리했습니다.

## 8. Lucent가 요청하는 권한

| 권한 | Lucent가 요청하는 이유 |
|---|---|
| 네트워크 접근(Android `INTERNET`) | 설정한 어시스턴트 제공자에게 메시지 보내기, 켰을 때의 웹 검색, 켰을 때의 WebDAV 백업, 켰을 때의 업데이트 확인. 이 중 어느 것도 활성화되어 있지 않으면 아무것도 전송되지 않습니다. |
| 알림(Android `POST_NOTIFICATIONS`) | 할 일 알림 표시, 그리고 당신이 시작한 다운로드, 백업, 생성 작업의 진행 상황 표시. |
| 정확한 알람(Android `SCHEDULE_EXACT_ALARM`) | 할 일 알림이 대략의 시각이 아니라 당신이 정한 시각에 울리게 하기 위해. |
| 시작 시 실행(Android `RECEIVE_BOOT_COMPLETED`) | 기기를 다시 시작한 뒤 알림을 다시 등록해, 내일로 잡아 둔 알림이 재부팅을 넘어 살아남게 하기 위해. |
| 포그라운드 서비스(Android `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_DATA_SYNC`) | 앱이 앞에 없을 때도 백업, 다운로드, 모델 생성을 끝까지 진행해 중간에 종료되지 않게 하기 위해. |
| 생체 인증 잠금 해제(Android `USE_BIOMETRIC`, Windows에서는 Windows Hello) | 앱 잠금 비밀번호를 입력하는 대신 지문이나 얼굴로 앱을 열기 위해. 선택 사항이고 기본은 꺼짐이며, 로컬 잠금 해제에만 쓰입니다. |
| 진동(Android `VIBRATE`) | 입력할 때의 촉각과 진동 피드백. |
| 패키지 설치(Android `REQUEST_INSTALL_PACKAGES`) | 당신이 내려받기를 고른 업데이트를 시스템 설치 프로그램으로 설치하기 위해. |
| Shizuku 서비스 권한(Android `moe.shizuku.manager.permission.API_V23`) | 7절에서 설명한 선택적 특권 연동. Shizuku를 애초에 쓸 수 있게 하려고 선언하는 것뿐이며, 당신이 Shizuku를 설치해 허용하지 않으면 아무 효과도 없습니다. |

Lucent는 파일이나 저장소에 대한 광범위한 접근 권한을 요청하지 않습니다. 파일과 폴더는 당신이 시스템 기본 선택기로 고르고, Lucent는 고른 항목만 받습니다. 글꼴과 모델 파일도 같습니다. 당신이 고르면 앱 전용 저장 영역으로 복사됩니다.

## 9. 당신이 쥔 통제 수단

Lucent의 개인정보 보호는 일련의 스위치이며, 그 모두가 당신 손안의 설정에 있습니다. 주요 항목은 다음과 같습니다.

- **앱 잠금.** 설정 → 보안. 비밀번호를 정하고, 필요하면 잊었을 때를 위한 보안 질문도 정합니다. 저장되는 것은 솔트가 섞인 해시뿐입니다.
- **잠금 해제 시도 횟수 제한.** 앱 잠금과 같은 화면. 첫 번째 라운드와 이후 라운드에서 허용할 시도 횟수를 정합니다. 실패하면 단계적으로 길어지는 대기 시간이 생기고, 이는 재시작을 넘어 유지됩니다.
- **반복 실패 후 데이터 삭제.** 역시 앱 잠금 화면에 있으며 기본은 꺼짐. 정한 횟수만큼 비밀번호를 틀리면 모든 것이 삭제됩니다. 영구적이며 누구도 되돌릴 수 없습니다.
- **생체 인증 잠금 해제.** 선택 사항이고 기본은 꺼짐.
- **블랙아웃 모드.** 설정 → 개인정보. 켜져 있는 동안에는 아무것도 기기 밖으로 나가지 않습니다. 클라우드 어시스턴트, 웹 검색, 네트워크 기능이 차단되고, 클라우드 관련 화면은 얼어붙고, 앱은 최근 사용 목록에서 숨겨지며 화면 캡처도 막히고, 공유 대상에서도 빠지고, 돌아올 때마다 비밀번호가 필요합니다. 다른 모든 설정보다 우선하며, 끄면 이전 설정으로 돌아갑니다.
- **진단 로그.** 설정 → 개인정보. 기본은 꺼짐이고 명시적인 동의가 필요합니다. 로컬에만 기록하며 어시스턴트에게 입력한 텍스트를 포함할 수 있고, 당신이 내보낼 수 있으며, 언제든 지우고 끌 수 있습니다. 크래시 실드를 켜면 잡아낸 오류가 기록되도록 이 기능이 켜진 상태로 고정됩니다.
- **크래시 실드.** 설정 → 개인정보. 기본은 꺼짐. 앱 내부의 오류를 잡아 앱이 닫히지 않고 열린 채로 남게 하고, 그 내용을 로컬에 기록합니다. 잡지 못하는 것도 분명히 밝힙니다. 온디바이스 모델 엔진 내부의 충돌, 메모리 확보를 위해 시스템이 앱을 종료하는 경우, 응답 없음으로 시스템이 앱을 종료하는 경우입니다.
- **시스템 연동.** 설정 → 개인정보. 기본은 꺼짐. Lucent가 다른 앱의 공유 시트에 나타나도 되는지를 정합니다.
- **버전 기록.** 설정 → 개인정보. 노트 기록과 할 일 기록을 각각 끌 수 있고, 끄면 새로운 스냅샷이 남지 않습니다.
- **어시스턴트 제공자와 기억.** 설정 → 어시스턴트에서 다시 클라우드 모델 또는 로컬 모델로 들어갑니다. 제공자를 고르거나, 네트워크를 전혀 쓰지 않는 로컬 모델을 가져와 씁니다. 기억 설정은 모델마다 따로 있으며 요청마다 포함할 지난 대화의 양을 정합니다. 낮출수록 기기 밖으로 나가는 텍스트가 줄어듭니다.
- **웹 검색.** 설정 → 어시스턴트 → 개인화. 스위치는 하나이며 기본은 꺼짐이고, 옆에서 검색 엔진을 고릅니다. 로컬 모델을 에이전트 모드 없이 쓰는 동안에는 쓸 수 있는 것이 없어 숨겨지고, 이후 그대로 돌아옵니다.
- **시맨틱 검색.** 설정 → 어시스턴트. 사용 중인 모델을 따릅니다. 로컬 모델이면 색인이 기기 안에, 클라우드 모델이면 텍스트가 제공자에게 전송됩니다. 모델을 바꾸면 동작도 바뀌고, 어시스턴트를 쓰지 않으면 아무 일도 일어나지 않습니다.
- **백업 내용과 비밀번호.** 설정 → 데이터. 백업에 무엇을 담을지, 비밀번호로 보호할지를 정합니다. 자동 백업, 그 폴더, 주기, 보관할 사본 수는 모두 당신이 정하는 것이며 기본은 꺼짐입니다.
- **클라우드 백업.** 설정 → 데이터. 기본은 꺼짐. WebDAV 자격 증명은 언제든 입력하거나 지울 수 있습니다.
- **암호화 검사.** 설정 → 보안. 저장된 값이 봉인되어 있고 올바르게 열리는지 필요할 때 확인합니다.
- **전체 데이터 삭제.** 설정 → 데이터. 10절을 보십시오.

## 10. 보관과 삭제

Lucent는 당신이 지울 때까지 데이터를 기기에 보관합니다. 삭제한 노트와 할 일은 먼저 휴지통에 들어가고, 휴지통을 먼저 비우거나 전체 데이터를 삭제하지 않으면 30일 뒤에 완전히 제거됩니다. 버전 기록은 해당 기록 설정이 켜져 있는 동안에만 유지되며, 속한 노트나 할 일과 함께 사라집니다.

모든 것을 지우려면:

- **설정 → 데이터 → 전체 데이터 삭제**는 모든 노트, 할 일, 대화를 지우고 첨부파일을 제거하며, 기록을 비우고, API 키를 포함한 설정을 기본값으로 되돌리고, 가져온 모델과 글꼴을 삭제하고, 로컬 진단 로그를 지우고 로그를 끄며, 앱 캐시를 비웁니다. 되돌릴 수 없습니다. 노트만, 할 일만, 채팅 기록만 지우는 개별 기능도 있습니다.
- Android 또는 Windows 시스템 설정에서 **앱 데이터 지우기**를 하면 같은 방식으로 앱의 저장 영역이 제거됩니다.
- **Lucent를 삭제(언인스톨)**하면 앱과 그 비공개 저장 영역이 제거됩니다.

Lucent의 손이 닿지 않는 것이 세 가지 있으며, 앱이 대신 지워 줄 수 없습니다.

- 폴더, 다른 기기, 클라우드 서비스로 내보낸 백업 파일
- 이미 WebDAV 서비스에 업로드한 백업
- 어시스턴트를 통해 AI 제공자에게 보낸 내용, 또는 검색 서비스에 보낸 내용. 이에는 해당 제공자 자신의 보관 정책이 적용됩니다.

이것들도 지우고 싶다면 파일을 삭제하고 제공자가 마련한 삭제 기능을 사용하십시오.

## 11. 아동

Lucent는 범용 노트 및 할 일 앱입니다. 아동을 대상으로 하지 않으며, 계정 체계도 광고도 소셜 기능도 없고, 개발자는 아동을 포함해 누구에게서도 개인정보를 수집하지 않습니다. 앱의 데이터는 그것을 쓰는 사람의 기기에 남습니다.

## 12. 이 방침의 변경

향후 Lucent 버전에서 데이터 처리 방식이 바뀌면 이 방침을 갱신하고 맨 위의 날짜도 바뀝니다. 실질적인 변경, 즉 기기 밖으로 나가는 데이터에 영향을 주는 변경은 그것을 도입한 버전의 릴리스 노트에 적습니다. 당신에게 적용되는 방침의 판본은 당신이 실행하는 Lucent에 함께 포함된 것이며, 그 이력은 저장소의 커밋 기록에서 확인할 수 있습니다.
