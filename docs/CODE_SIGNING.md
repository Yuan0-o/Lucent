# Code-signing the Windows installer

The Windows pipeline (`.github/workflows/build-windows.yml`) contains an **optional, secrets-gated
signing step**: when the two repository secrets below exist, every produced installer is
Authenticode-signed and verified before upload; when they don't, the build still succeeds and
uploads an unsigned installer with a notice. Signing can never be the reason a build fails to exist.

| Repository secret | Contents |
|---|---|
| `LUCENT_SIGN_PFX_BASE64` | The `.pfx` certificate file, encoded to base64 text |
| `LUCENT_SIGN_PFX_PASSWORD` | The password chosen when exporting the `.pfx` |

## What a self-signed certificate does — and does not — buy

**Does:** a verifiable publisher identity on the file (right-click → Properties → Digital
Signatures shows *Yuan, Z-ERA Singularity Synthesis Technology Co., Ltd.*), tamper evidence (any
byte change breaks the signature), and a consistent identity across releases. With the RFC-3161
timestamp the workflow applies, signatures remain valid even after the certificate expires.

**Does not:** remove the SmartScreen "unknown publisher" prompt. SmartScreen trusts *reputation*
and *publicly-trusted CAs*; a self-signed certificate is neither. Removing that prompt requires a
paid, identity-verified OV certificate (reputation builds over time) or EV certificate (immediate).
This is a product cost decision, not a workflow change — the pipeline step is identical either way:
export whichever certificate to a `.pfx` and update the two secrets.

## Generating the certificate (one-time, on any Windows PC)

Run in **PowerShell** (not cmd). This creates a 50-year self-signed code-signing certificate with
the maintainer's identity, exports it password-protected, and prints the base64 for the secret:

```powershell
$cert = New-SelfSignedCertificate `
  -Type CodeSigningCert `
  -Subject "CN=Yuan, O=Z-ERA Singularity Synthesis Technology Co., Ltd., L=New York, S=New York, C=US" `
  -KeyAlgorithm RSA -KeyLength 3072 -HashAlgorithm SHA256 `
  -KeyExportPolicy Exportable `
  -NotAfter (Get-Date).AddYears(50) `
  -CertStoreLocation Cert:\CurrentUser\My

$pwd = Read-Host -AsSecureString "Choose a certificate password"
Export-PfxCertificate -Cert $cert -FilePath "$env:USERPROFILE\Desktop\lucent-sign.pfx" -Password $pwd

[Convert]::ToBase64String([IO.File]::ReadAllBytes("$env:USERPROFILE\Desktop\lucent-sign.pfx")) |
  Set-Clipboard
Write-Host "Base64 of the .pfx is now on the clipboard - paste it into the LUCENT_SIGN_PFX_BASE64 secret."
```

Then in GitHub: **Settings → Secrets and variables → Actions → New repository secret**, create
`LUCENT_SIGN_PFX_BASE64` (paste from clipboard) and `LUCENT_SIGN_PFX_PASSWORD` (the password you
typed). Run the Windows workflow; the log shows `Installer signed`.

## Security notes

- The `.pfx` **is** the signing identity. Keep the desktop copy somewhere safe (or delete it after
  uploading the secret — it can be re-exported from the certificate store), and never commit it.
- The private key is generated on the maintainer's own machine and travels only into GitHub's
  encrypted secret store. It is deliberately **not** generated by any third party or tool run
  elsewhere: whoever holds the key can sign as this identity.
- Rotating: generate a new certificate the same way and overwrite the two secrets. Old installers
  keep their (timestamped) signatures.
